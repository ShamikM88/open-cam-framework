# Security Policy

This is a public, forkable framework repository. Never use a public issue or pull request to disclose a vulnerability in detail or an accidental exposure of real lending data, personal information, credentials or keys.

## Reporting a vulnerability or confidential-data exposure

**Preferred private channel:** GitHub's private vulnerability reporting for this repository. When the maintainer has enabled it, open the repository's **Security** tab and choose **Report a vulnerability**. This submits a private report rather than a public issue. The control is a GitHub repository setting; this file does not enable it.

If **Report a vulnerability** is not available, do not post technical details, exploit steps, real data or secrets publicly. Use an already available private contact route for the repository maintainer only to request an approved disclosure channel; do not include the sensitive report until a private route has been agreed. The maintainer should enable GitHub private vulnerability reporting so there is a discoverable, supported channel.

## What to include in a private report

Use synthetic examples wherever possible. Include the affected file, command or workflow; the relevant commit or release; the impact you observed; a minimal reproduction using synthetic data; and any mitigation you believe would help. Remove names, identifying information, real figures, document excerpts, tokens and credentials from logs or screenshots.

## What not to include

Do not include real borrower or customer names, real financial figures or deal documents, personal data, private keys, API keys, access tokens, passwords, or unredacted production logs. Do not attach confidential source material to a public issue or pull request.

## Response and coordination

The maintainer will assess the report, coordinate a fix and decide whether a security advisory or other notification is appropriate. Do not assume a response time or disclosure date; agree on next steps privately after the report is received.
